# Implementation Plan: Max Test Bench

**Spec**: `.specify/test_bench/spec.md`
**Created**: 2026-09-22
**Status**: Implemented 2026-09-22 — ADRs carry as-built revisions

## Summary

One small, generated Max patch (`tests/bench/bench.maxpat`) plus one JS
file (`tests/bench/bench.js`) that owns all sequencing. The patch stays
open; Python triggers jobs over OSC/UDP and exchanges data through files in
a per-job directory. Codeboxes arrive as generated `.genjit` files loaded
via `jit.gl.pix`'s `gen` attribute; textures move as float32 `.jxf`. Python
(`tests/jxf.py`, `tests/genjit.py`, `tests/benchclient.py`) writes jobs,
waits, reads results and diffs against the NumPy mirrors.

Facts established from Max 9's own reference docs and shipped files
(2026-09-22), not yet tested live:
- `jit.gl.pix` has `gen` (gen patcher name), `adapt` (default 1), `dim`
  (default 256 256, used when `adapt 0`), `type` (incl. float32), `bypass`,
  plus `compile` / `file` / `exportcode` / `full_source_code`. **No inline
  `expr` attribute** — code must arrive as a gen patcher file.
- `jit.matrix` has a `jit_gl_texture` method: copies a named texture into
  the matrix — the float32 readback path. `read`/`write` handle `.jxf`.
- `jit.gl.asyncread` reads the GL context (framebuffer) via PBOs, not a
  texture — not used.
- `error` object: while listening (`error 1`), outputs every Max error from
  any patch as a message — the error capture path (max-test's console
  check uses exactly this).
- `jit.world`: `fps` (default 30) and `sync` (default 1, swap-synced)
  cap rendering — perf mode must lift both.
- `.jxf` format, decoded from `C74/help/jitter/matrix1.jxf` (big-endian
  IFF-style): `FORM` + total size + `JIT!`; `FVER` chunk (size 12, version
  `0x3C93DC80`); `MTRX` chunk: chunk size, data offset from chunk start
  (`0x20`), type 4cc (`LONG` seen; `FL32` expected for float32), planecount,
  dimcount, dims (dim0 = width), then cell-interleaved data. Verified by
  size arithmetic: 320×240×2 planes×4 bytes + 32 = MTRX size.
- `.genjit` = patcher JSON (`Examples/jitter-examples/gen/*.genjit`).

## Architecture Decisions

### ADR-1: All bench logic in one JS file; the patch is only objects and wiring

**Context:** Job sequencing (read job, set attributes, load inputs, count
frames, collect errors, capture, write report, reply) in pure Max messages
means dict-iteration and trigger-order spaghetti that is hard to read,
hard to diff and easy to get subtly wrong — the exact class of patch this
bench is meant to eliminate.

**Decision:** A single classic `js` object running `tests/bench/bench.js`
(ES5, same engine as the repo's existing `package/javascript/` files) holds
all logic. It reads `job.json` with the JS `File` API + `JSON`, messages
named objects via `this.patcher.getnamed(...)`, receives per-frame bangs
and `error` output, writes `result.json`, and emits the reply. `js` is part
of Max, so NF-001 (no externals) holds.

**Consequences:** Logic is text — reviewable, greppable, editable by
Desktop Commander. JS runs in the low-priority queue; frame-timing numbers
come from the world's draw bangs, so queue latency affects scheduling but
not measured GPU work. `v8` is the fallback if classic `js` lacks anything.

### ADR-2: The patch is generated by a script, not hand-built

**Context:** Hand-built patches drift and can't be reviewed as diffs; the
build system already generates patcher JSON reliably.

**Decision:** `tests/bench/make_bench.py` writes `bench.maxpat` (~20–25
objects). Regenerating is always safe — the bench has no hand-built UI to
lose (unlike the modules on the never-regenerate list).

**Consequences:** Matt's only manual step is opening it and confirming it
loads clean. Object-class mistakes (cf. the `numbox` vs `flonum` slip in
the `f_a_ripple` build) are caught at that first open.

### ADR-3: Codebox delivery — unique-name `.genjit` next to the bench, via `gen`

**Context:** No inline-code attribute exists. `gen` takes a patcher *name*
resolved through Max's search path, which includes the patcher's own
folder. Reusing one filename risks Max serving a cached compile — the
stale-state trap that has bitten `f_apollonian` twice.

**Decision:** Python writes each job's codebox as
`tests/bench/job_<id>.genjit` (unique per job), and the bench sets
`gen job_<id>`. Old job files are deleted by Python after the run.
Fallbacks, in order, if self-test 3 (reload) fails: (a) `file` attribute
with an absolute path; (b) send `compile` after setting `gen`; (c) script
the pass object's deletion and recreation via `thispatcher`.

**Result (2026-09-22, T020):** works as designed — consecutive jobs
recompile immediately; no fallback needed. Cleanup refined: the loaded
`.genjit` is kept until the next job loads a different one (deleting the
loaded file makes Max try to reload it and post "could not find gen
patcher").

**Consequences:** Self-test 3 is the gate for this ADR. The genjit
generator is a small standalone function in `tests/genjit.py` (not an
import of `build_patcher.gen_subpatcher`, whose archetype/mod-inlet logic
is module-specific), structurally cross-checked against a shipped Max
example.

### ADR-4: Data transfer as float32 `.jxf`; upload and readback through `jit.matrix`

**Context:** Correctness diffs need exact float32 values in both
directions; image formats are 8-bit.

**Decision:** Inputs: Python writes `inN.jxf` (`FL32`, 4 planes) →
`jit.matrix @type float32 @planecount 4` `read` → `jit.gl.texture @type
float32`. Output: pass output texture → `jit.matrix @type float32` via its
`jit_gl_texture` method → `write out.jxf`. `tests/jxf.py` owns read/write
and converts to/from the RGBA `(H, W, 4)` arrays `gpu_sim.py` uses.

**Consequences:** Two unknowns handled by self-tests, not assumed: (1)
Jitter's plane order for float texture readback (likely ARGB, i.e. alpha
first, as for char matrices); (2) row order (matrix row 0 vs `norm.y`).
Both are resolved once by the coordinate probe (ADR-7) and then baked into
`jxf.py`'s conversion, with a comment citing the evidence.

### ADR-5: Control over OSC/UDP both ways; data and reports in files

**Context:** Python must trigger jobs and know when they finish; Max has
`udpreceive` / `udpsend` (OSC-native).

**Decision:** Python → bench on UDP 7471: `/ping`, `/run <abs job dir>`.
Bench → Python on UDP 7472: `/pong`, `/done <job dir>`, `/busy <job dir>`
(as built: replies carry the job *dir* the request named, so a refused job
is identifiable without the bench having parsed it).
The bench writes `result.json` *before* sending `/done`. Minimal OSC
encode/decode is hand-rolled in `tests/benchclient.py` (string args only,
~30 lines) — no `python-osc` dependency. Ports are constants in one place
on each side.

**Consequences:** Reachability check = `/ping` with a 1 s timeout. Job
overlap is refused by the bench (`/busy`), never interleaved. Python-side
per-job timeout covers hangs; the bench also has its own watchdog (ADR-9).

### ADR-6: Correctness taps slot 1 directly; performance uses an 8-slot chain with bypass

**Context:** Correctness wants exactly one pass and an uncontaminated
capture. Performance wants K chained copies of a stage.

**Decision:** The patch has 8 `jit.gl.pix` slots in series (`bench_p1`…
`bench_p8`), all given the same `gen`, `dim`, `type` and params; `in2`/`in3`
fan out to every slot. Correctness mode captures from `bench_p1`'s output
via its own tap and sets slots 2–8 to `bypass 1`. Performance mode enables
slots 1…K, bypasses the rest, and measures fps; a K=0 baseline (all
bypassed) is measured in the same job and reported alongside, so the cost
of bypassed pass-throughs is visible rather than hidden.

**Consequences:** K ≤ 8 in this version. Whether `bypass` is truly
near-free is itself measured, not assumed.

**Revision (2026-09-22, Phase 1):** `jit.gl.pix`'s `inputs` attribute is
read-only — the inlet count follows the loaded gen code — so physical cords
into inlets 1–2 would be deleted whenever a 1-input codebox loads. Only
inlet 0 of each slot is wired (`bench_tex1` → `bench_p1` → … → `bench_p8`).
Inputs 2–3 are delivered by `bench.js` per frame via the documented
`activeinput` attribute (set N, send `jit_gl_texture bench_texN+1`, reset to
0 before the physical inlet-0 texture arrives). Unverified until T014 runs a
2-input codebox.

**Revision 2 (2026-09-22, Phase 2) — the above failed; replaced.** Message
delivery doesn't work: `activeinput N` + `jit_gl_texture` landed on input 0,
and `sendinput N jit_gl_texture` left the input at its default. Final design:
the inlet count follows the gen patcher's `in` *objects*, not what the
codebox references — so every bench `.genjit` carries `in 1..3` (unused ones
unwired; `genjit.make_genjit(min_inputs=3)`) and all slots load a committed
3-input `bench_default.genjit` at patch load. Inlet counts never change, and
`bench_tex2`/`bench_tex3` are ordinary physical cords into inlets 1/2 of
every slot. Also learned: the pix re-renders every frame on its own; its
inputs are set once, when the input matrices are banged at job start (the
per-frame bang to `bench_tex1` does not re-send the texture).

### ADR-7: Coordinate probe as a self-test, feeding back into `gpu_sim.py`

**Context:** The identity self-test is orientation-blind — an upload flip
and a readback flip cancel out. `gpu_sim.py` explicitly labels its
y-orientation and texel-center conventions as sim conventions, not claims
about Jitter.

**Decision:** Self-test 1b runs a probe codebox writing
`vec(norm.x, norm.y, cell.x, cell.y)` (and a constant `vec(1,2,3,4)` job
for plane order). Python checks: norm values are texel centers
`(cell + 0.5)/dim`; which matrix row holds `norm.y ≈ 0`; which plane holds
which channel.

**Consequences:** Outcomes get written into `jxf.py`'s conversion and, if
needed, `gpu_sim.py`'s documented conventions, with the probe as cited
evidence. Probe results also land in the `jit-gen-codebox` skill as
empirically verified facts about `norm`/`cell`.

### ADR-8: Bench tests are separate from math tests

**Context:** `tests/run.sh` must stay runnable anywhere (no Max). Bench
tests need Max open.

**Decision:** Bench tests are named `tests/bench_*.py` and run via
`tests/bench.sh`; `tests/run.sh` keeps running only `test_*.py`. Offline
parts of the bench toolchain (`jxf.py`, `genjit.py`, OSC encoding) get
ordinary `test_*.py` coverage — including parsing Max's shipped
`matrix1.jxf` as an independent format check.

**Consequences:** `bench.sh` fails fast with "bench not reachable" when Max
isn't up (spec Story 4 scenario 2).

### ADR-9: Rendering and frame sequencing

**Context:** Frames are asynchronous; jobs must wait for compile, then
capture or time frames. `jit.world` defaults cap at 30 fps, swap-synced.

**Decision:** The bench has its own small visible `jit.world bench_ctx`
(not Vsynth's context). Its per-frame draw bang drives the input textures
and counts frames in `bench.js`. Correctness: `warmup` frames (default 3),
then capture on the next frame. Performance: world `sync 0`, high `fps`,
`warmup` 30 frames, then time `frames` (default 120) draw bangs with
`max.time`-based deltas; report mean fps. Watchdog in `bench.js`: if no
frame arrives within the job's `timeout_ms`, write `status: stalled`.

**Consequences:** fps is wall-clock throughput of the whole world frame
(including bypassed slots and the frame overhead) — useful for
*comparisons* between codeboxes and K values, not an absolute GPU-time
measurement. Stated explicitly in reports.

**Revision (2026-09-22, Phase 1):** measured 177 draw bangs in 1.5 s
(~118 fps) with `@enable 1` and the default `fps 30` — the world runs
display-synced (probably displaylink on a 120 Hz display), not at its `fps`
attribute. Perf mode must take explicit control of the rate (e.g.
`displaylink 0` + `sync 0` + high `fps`, or manual `enable 0` + banging)
and record which in the report. Correctness mode is unaffected.

**Revision 2 (2026-09-22, Phase 4) — measurement model.** Implemented as
`displaylink 0` + `sync 0` + `fps 1000`, restored after each job. CPU and
GPU work overlap: frame time ≈ max(CPU overhead, K × pass cost) — verified
with a ~9 ms synthetic codebox (K=1 8.8 ms, K=2 17.3 ms) and the N=512 DFT
at K=1/2/4/8. So the baseline-subtraction estimate above is wrong: per-pass
cost = frame time / K, valid only when a run is GPU-bound; below that, only
an upper bound (overhead / K) is available. The K=0 baseline is kept to
classify runs. Params move to frame 3 (a new gen compiles at its first
render; the draw bang precedes it). `bench_src` (identity pix) feeds slot 1
like the other slots.

## Job and report formats

`<job dir>/job.json`:
```json
{
  "id": "20260922-0001",
  "mode": "correctness",
  "gen": "job_20260922-0001",
  "dim": [128, 128],
  "type": "float32",
  "inputs": ["in1.jxf"],
  "params": {"inverse": 0},
  "warmup": 3,
  "chain": 1,
  "frames": 120,
  "timeout_ms": 10000
}
```

`<job dir>/result.json`:
```json
{
  "id": "20260922-0001",
  "status": "ok | error | stalled",
  "errors": ["gen: ..."],
  "frames_rendered": 4,
  "output": "out.jxf",
  "fps": null,
  "fps_baseline_k0": null,
  "elapsed_ms": 412
}
```

`status: ok` means *ran and captured*, nothing more — numeric correctness
is judged Python-side. Job dirs live under `tests/jobs/` (gitignored).

## Python API (sketch)

```
benchclient.ping() -> bool
benchclient.run_pass(codebox, inputs=[rgba,...], dim=(w,h), params={}, warmup=3)
    -> (output_rgba or None, report)
benchclient.measure(codebox, inputs, dim, chain=K, frames=120)
    -> report   # fps, fps_baseline_k0
```
Multi-pass correctness (e.g. FFT) = successive `run_pass` calls feeding
each output into the next job (spec decision: one pass per job).

```
tests/
  jxf.py                 .jxf read/write <-> RGBA float32 arrays
  genjit.py              codebox text -> .genjit JSON
  benchclient.py         OSC ping/run, job dirs, timeouts, run_pass/measure
  test_jxf.py            offline: round trip + parse Max's matrix1.jxf
  test_genjit.py         offline: structure vs shipped example
  test_benchclient.py    offline: OSC encode/decode round trip
  bench.sh               runs tests/bench_*.py (needs Max + bench open)
  bench_selftest.py      Story 1: identity, probe, broken, reload
  bench_fft.py           Story 2: FFT T1 (row pass N=128) vs NumPy
  bench_perf.py          Story 3: fps, K chains
  bench/
    make_bench.py        generates bench.maxpat
    bench.maxpat         generated
    bench.js             all sequencing logic
    codeboxes/           .gen files under test (e.g. dft_x.gen)
  jobs/                  runtime, gitignored
```

## Dependency Blocks

### Block 0: Offline toolchain (no Max)
**Dependencies:** none.
**Builds:** `jxf.py`, `genjit.py`, OSC encode/decode in `benchclient.py`,
their `test_*.py`.
**Verification:** offline tests pass; `jxf.py` parses Max's shipped
`matrix1.jxf` header and data consistently (dims 320×240, 2 planes, LONG).

### Block 1: Bench patch + JS, reachability
**Dependencies:** Block 0 (OSC encoding).
**Builds:** `make_bench.py`, `bench.maxpat`, `bench.js` (ping + job skeleton).
**Verification:** Matt opens the bench: loads with a clean console;
`benchclient.ping()` returns true; ping with the bench closed fails fast.

### Block 2: Self-verification (spec Story 1)
**Dependencies:** Block 1.
**Builds:** full correctness path in `bench.js`; `bench_selftest.py`.
**Verification:** identity bitwise-exact; probe resolves orientation /
texel centers / plane order (recorded, conversions updated); broken
codebox → `status: error` with text; reload → second codebox's output.
Decision gates for ADR-3 fallbacks and the error-capture route live here.

### Block 3: FFT T1 through the bench (spec Story 2)
**Dependencies:** Block 2.
**Builds:** `codeboxes/dft_x.gen` (GenExpr translation of
`test_fft_separable.pass_dft`, carrying the three findings: `nearest()` at
texel centers, `mod(k*n, N)` before the angle, signed wavenumber via
`switch`); `bench_fft.py`.
**Verification:** either a printed float32 error vs NumPy within tolerance,
or a *distinct, reported* failure mode (compile error / black / stall) —
both are answers to T1.

### Block 4: Performance mode (spec Story 3)
**Dependencies:** Block 2 (Block 3 for a meaningful subject).
**Builds:** perf path in `bench.js` (world `sync 0`, K slots, baseline);
`bench_perf.py`.
**Verification:** K=1 vs K=8 fps differ plausibly; repeat runs agree within
10%; baseline reported.

### Block 5: Records
**Dependencies:** Blocks 2–4.
**Builds:** `tests/README.md` bench section; findings into the
`jit-gen-codebox` skill (norm/cell conventions, error capture, loop compile
result); ceyron notes FFT status; HANDOFF.

## Risks

**Materialized (2026-09-22):** an unbuffered `[error] → js` wire can recurse
into a Max stack overflow, which disables *all* outlets in Max until the
flag is cleared by hand — fixed with `[deferlow]` + `[prepend bench_error]` +
a never-throwing handler (tasks.md T019). Error capture itself works: gen
compile errors do reach `[error]`.

- **Gen compile errors may not route through `error`** (they might only
  post as warnings, or be reported by `jit.gl.pix` differently). Fallback:
  treat "no errors + all-zero output" as suspected compile failure, and
  query `jit.gl.pix`'s `getparamlist`/`full_source_code` after load to
  detect an empty compile. Decided at Block 2.
- **Search-path resolution of newly written `.genjit` files** may not be
  live. ADR-3 fallbacks.
- **Float texture readback may be clamped or 8-bit** despite `@type
  float32` on the matrix. The identity self-test uses values outside [0,1]
  specifically to catch this.
- **`js` File API write permissions / path handling** on absolute paths
  outside the patch folder. Fallback: job dirs inside `tests/bench/`.
