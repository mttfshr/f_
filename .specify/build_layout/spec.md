# Spec: Edit-View Layout Pass for `build_patcher.py`

**Status**: Implemented 2026-09-24 (Phases 0–2 and 4); Phase 3 done for the 10 modules that regenerate cleanly (`f_caustic`, `f_stipple`, `f_vf_glow`, `f_vf_prism`, `f_vf_streak`, `f_ngon`, `f_vf_chroma`, `f_vf_potential`, `f_vf_split`, `f_chladni`), awaiting Matt's look in Max (T014). Scope decided with Matt: **generated modules only** (see Scope). **Finding:** 29 of 33 definitions have drifted from their shipped patchers, so "generated modules" is much narrower than assumed — see tasks.md "Drift survey" and T018.
**Tasks**: `.specify/build_layout/tasks.md`

## Problem

`build_patcher.py` lays out the **presentation** view from a real spec (5 dials per
row, 37 px pitch, 62 px row height, label offsets — `build/spec.md` "UI Layout") but
lays out the **edit view** (`patching_rect`) from hardcoded per-box-type magic numbers
that never reference each other:

- dials / numboxes / menus all at `[50 + n*50, 80]` (same origin across types),
  labels at `[50 + n*50, 130]`, attrui/`prepend` boxes staggered diagonally at
  `[50 + n*50, 170 + n*30]` — a single linear row vs. the presentation's 5-wide grid
- `routepass` / `route` / pix fixed at x=200 regardless of param count; the route box's
  width comes from its text length, so its outlets do not line up over the dials
- `pix_chain` nodes at `[200, 380 + support_index*60]`; gen subpatcher internals have
  their own fixed slots
- the background panel is `background: 1` at `[20, 20, pw, ph]`, so a black rectangle
  is painted behind the top-left of the edit view, exactly where the objects pile up

Result: running the build produces a messy edit view. Baseline measured 2026-09-24
with `scratch/edit_layout_audit.py` (deleted 2026-10-06; in git history, `git log --diff-filter=D -- scratch/edit_layout_audit.py`) (overlapping `patching_rect` pairs):
f_droste 13, f_vf_fluid 33, f_stipple 38, f_vf_glow 39, f_vf_prism 62,
f_masonry (hand-edited, for reference) 150.

## Scope

**In:** modules generated by `build/build_patcher.py` from `src/<m>/definition.py`.

**Out (for now, Matt's call 2026-09-24):** the never-regenerate / hand-edited modules
(`f_masonry`, `f_sirds`, `f_vf_advect`, `f_vf_seeds`, `f_grain`, `f_vf_warp`, `f_lens`,
and the drifted `f_vf_fieldmap` / `f_vf_repulse`) — no standalone retrofit tool.
Keep `layout.py` callable on a plain patcher dict so a retrofit tool stays possible
later, but do not build one now.

**Follow-up, not decided:** `build_fluid.py` (and other per-module builders that import
shared chrome from `build_patcher.py`) can call the same pass; `f_vf_fluid` is
script-generated and not yet hand-edited.

## Design

1. **Separate pass, own module.** New `build/layout.py` exposing
   `layout_edit_view(boxes, lines, roles)`, called once at the end of `build()`.
   Boxes keep being created with placeholder rects; the pass rewrites **only**
   `patching_rect`. It never touches `presentation_rect`, object IDs, box order (pix must
   precede the bypass jsui — `param_connect` dependency) or patchlines.
2. **Zone-based, role-tagged — not a generic graph solver.** The builder knows each
   box's role at creation, so roles are tagged there (a separate `{id: role}` dict returned
   alongside `boxes` — decided 2026-09-24; `box()` output stays byte-identical and roles are
   never serialized into the `.maxpat`) rather than inferred from wiring. Zones:
   - *Signal strip*, top to bottom: inlet → `routepass` → pix / `pix_chain` → outlets;
     mod inlets and `vs_inState` beside the inlet.
   - *Param lane*: one column per param in definition order; each column stacks
     label, dial/numbox/menu, and its `prepend`/attrui so wires run straight down to
     the pix. Range-tier objects hang off their dial's column.
   - *Service corner*: moduleSize chain, `autopattr`, bypass jsui/`prepend`,
     panel-toggle objects — grouped, out of the signal path.
   A layered-graph (Sugiyama-style) layout is the fallback for unrecognized boxes only.
3. **Route box sets the pitch.** Route `patching_rect` width = N × column pitch, so
   outlet *n* sits over column *n* and wires run vertical.
4. **Panel relocated** to a fixed corner offset so it no longer sits behind working objects.
5. **Column order = presentation slot order** (n-th param → n-th edit column), even
   though presentation wraps at 5 per row and the edit lane is linear — keeps the two
   views easy to cross-reference.
6. **Deterministic and grid-snapped.** Pitch, row height and zone origins live in one
   constants block; rebuilds yield minimal, stable diffs.

## Defaults on open questions (change if Matt objects)

- Gen subpatcher internals (in → codebox → out): leave as is.
- `raw_boxes` from `definition.py` keep their own coordinates; the pass parks them in a
  labeled overflow area since it cannot know what they are.
- Small zone-label comments ("signal", "params", "service") in the edit view for orientation.

## Addendum 2026-10-05: `route_bypass`

When the definition sets `route_bypass` (`build/spec.md`), `bypass` is the route's first token and its
outlet 0 is wired to the bypass jsui. The pass detects it from the route text. Lane column 0 then
belongs to that outlet: the bypass jsui sits in the control row and its prepend in the attrui row of
column 0, and the params start at column 1, so each route outlet still sits over its own control and
no cord runs upward (the service-area position, above the route row, would make the route -> jsui cord
upward). Without the flag nothing changes. Tests: `test_route_bypass_keeps_each_route_outlet_over_its_control_and_wires_downward`.

## Addendum 2026-10-05: `route_first`

When the route's reject outlet feeds `routepass` (`route_first` in `build/spec.md`; f_grain), the pass
detects the route -> routepass cord and puts `routepass` and `vs_inState` below the param lane
(`Y_PRE + 50`, then +50), and moves the pix stack down by `RF_PIX_SHIFT` (100) to make room, so that
cord and everything after it runs downward. Without it nothing changes. Test:
`test_route_first_puts_routepass_below_the_route_and_wires_downward` (processor and dual).

## Addendum 2026-10-05: the service area clears the route box

The route box is never clipped below its text (`len(text) * 6.5`), which is wider than its lane columns
(72 px each) when token names are long. The service area (`x_a`) used to look at the lane columns only,
so it could start inside the route box (f_lens, once its tilt-shift tokens were gone: `moduleSize.js` at
x=1000 inside a route that ran to x=1090). `x_a` is now at least the route box's right edge plus the
service gap. Test: `test_the_service_area_clears_a_route_box_that_is_wider_than_the_lane`.
